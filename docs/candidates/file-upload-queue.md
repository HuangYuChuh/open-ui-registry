## 产品价值

该候选不仅提供拖放区域，还包含：

- 上传中、成功和失败状态；
- 文件列表；
- 移除与重试操作；
- 文件类型、大小和数量限制；
- 由使用方注入的异步上传函数；
- 进度与错误信息的基础无障碍语义。

它比单一文件选择框更符合“文件上传队列”槽位，也没有绑定特定云存储或后端服务。

## 必须处理的问题

### 1. 自动重试上限

上游在 `autoRetry` 为 `true` 且未提供 `maxRetryCount` 时以 `Infinity` 作为上限。持续失败的上传可能无限重试。适配版本必须使用有限默认值，或要求显式提供重试次数。

### 2. 中文与无障碍文案

源码包含 `dropzone`、`Remove file`、`Retry`、`indeterminate` 和 `error` 等英文标签。适配版必须提供简体中文默认值，并允许使用方覆盖；错误、进度和状态变化应由适当的 live region 播报。

### 3. 键盘与点击行为

拖放不能成为唯一输入方式。文件选择按钮必须可通过键盘操作，移除和重试按钮需要清晰名称、可见焦点及禁用语义。

### 4. 技术标准升级

需要验证 React 19、Tailwind CSS 4、Next.js 16 静态构建和 SSR 边界。上游本地 `Button` 与 `cn` 引用应适配为组件内明确实现或 Registry 依赖，不能假设使用方已有隐藏文件。

### 5. 中文内容布局

必须覆盖中文文件名、无扩展名文件、超长文件名、较长错误原因、多个文件和 375px 窄屏。文件名应截断但保留完整可访问名称。

### 6. API 收敛

原始单文件提供大量低层组合部件。适配前需要决定公开 API，避免把所有上游内部结构原样冻结为长期兼容契约。

## 建议适配边界

首版建议提供一个高层 `FileUploadQueue` 组件，而不是直接暴露全部内部部件：

- 由使用方传入 `onUpload(file, signal)`；
- 支持 `accept`、`maxFiles`、`maxSize` 和有限重试；
- 提供取消、移除和失败后重试；
- 默认显示中文状态与错误文案；
- 通过文案属性支持进一步本地化；
- 使用 CSS 变量与 `className` 定制；
- 不负责网络地址、鉴权或存储服务配置。

如果高层 API 无法覆盖后续需求，再把稳定的低层部件作为命名导出开放。
